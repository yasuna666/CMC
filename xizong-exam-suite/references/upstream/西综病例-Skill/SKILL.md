# 西综病例-Skill v2.2

> **专为西医综合病例分析题设计的临床工作流构建器**
> **核心原则**：完整题干前置展示 → 深度解析 → 决策链构建
> **版本**：v2.2（基于v2.1升级，消除冗余 + 防幻觉 + 自增长错误库）

---

## 零、触发条件

当用户输入包含以下关键词/意图时，激活本 Skill：

| 触发场景 | 示例用语 |
|----------|----------|
| 分析真题 | "分析2025年真题""提取病例题" |
| 创建工作流 | "做XX疾病的工作流""创建病例工作流" |
| 提取教材 | "提取急性心衰的教材内容" |
| 更新工作流 | "更新GAST-001""加2024年真题" |
| 查看进度 | "查看复习进度""还有哪些没做" |

**不触发**：单纯问医学知识问题、不涉及工作流生成的对话。

## 一、生成文档的强制结构

所有工作流必须严格按以下五章顺序组织，具体格式见 `template_v2.1.md`：

### 第1章：经典案例（学习用）【强制前置】

**位置**：文档第一章，必须在"临床决策链"之前

**必须包含三个子章节**：

- **1.1 完整题干展示**：100%复制真题共用题干，一字不减。包括患者基本信息、主诉、现病史、既往史、查体（阳性+阴性）、辅助检查（实验室+影像学）
- **1.2 完整答案解析（每题独立）**：每题必须包含6要素——【题目】【正确答案】【详细解析】【考查链条】【专家解读】【教材对应】
- **1.3 多题关联分析**：表格揭示3-4题之间的逻辑关系（因果链、时间轴推进等）

### 第2章：临床决策链（基于第1章深度解析）

- 每个决策节点必须明确引用第1章案例（【第1章案例对应】标记）
- 决策树基于第1章具体数据构建
- 节点数量根据疾病特点确定（通常3-5个）

### 第3章：考点速查表

- 3.1 必背诊断标准
- 3.2 决策时间窗/关键数值
- 3.3 真题易错点（引用错误模式库）

### 第4章：实战训练（3道其他真题）

- 每道包含：题干/问题/折叠答案/解析/与第1章经典案例对比/教材定位
- **训练题来源规则**（见"第三节"详述）

### 第5章：考频分析与审核

- 5.1 历年考查情况（表格：年份/题号/考查角度/难度/命题特点）
- 5.2 命题规律总结（必考点/高频点/易错点）
- 5.3 跨学科关联（生理学/病理学/药理学相关机制）
- 5.4 审核清单（四层）

## 二、标准操作流程（SOP）

### Step 0: 提取完整案例【前置步骤】

**输入**：真题文件

**如何定位真题文件**：
1. 读取项目根目录的 `project.yaml`，获取 `paths.exams` 和 `paths.root`
2. 当年真题（2025）：优先找根目录的 `2025年真题_最终标准版.md`
3. 历年真题（用于第4章训练题）：在 `真题/合并/` 目录下，文件名格式为 `{年份}年考研西医综合_真题+解析.md`
4. 如找不到文件，用 Glob 搜索 `*真题*标准版*.md` 和 `*真题*解析*.md`

**动作**：
1. 定位病例分析题组（第68-107题区间）
2. 完整复制共用题干（100%，不删减）
3. 逐题提取：题目（含ABCD选项）、正确答案、详细解析、题号标记
4. 格式标准化（为第1章做准备）

**质量检查点**：
- [ ] 题干完整性检查（与原文对比，差异<1%）
- [ ] 题目数量核对（3-4题全部提取）
- [ ] 答案与题号对应检查

---

### Step 1: 分析真题（基于Step 0的完整案例）

在已有完整案例基础上，进行：
1. 命题逻辑分析（每题考查什么能力）
2. 考查链条拆解（可视化流程图）
3. 多题关联分析（逻辑关系表）
4. 与历年真题关联（如有数据；如无，标注"仅分析当年"）

---

### Step 2: 创建待办清单

**动作**：
1. 生成工作流ID（如：CARD-001, GAST-001）
2. 确定系统分类（心血管/消化/呼吸等）
3. 创建/更新 `.progress.yaml` 条目（schema 见"第四节"）

---

### Step 3: 逐题组处理 - 生成第1章

按 `template_v2.1.md` 中"一、经典案例"的格式生成：
- 子步骤3.1：生成"1.1 完整题干展示"（直接复制 Step 0 提取的共用题干）
- 子步骤3.2：生成"1.2 完整答案解析"（每题按6要素格式）
- 子步骤3.3：生成"1.3 多题关联分析"

**来源验证规则（边写边验证）**：
在 Step 3-5 中，每引用一处教材内容，**立即**用 Read/Grep 工具读取教材文件验证，并在引用处标记 `verified: true/false/no_source`。不要等到 Step 6 才验证——Step 6 只做汇总检查。

---

### Step 4: 构建第2章（基于第1章深度解析）

1. 分析第1章案例的决策节点
2. 每个节点明确标注【第1章案例对应】
3. 构建决策树（引用第1章具体数据）
4. 生成专家解读（与第1章案例呼应）

---

### Step 5: 生成第3-5章

- **第3章**：考点速查表（诊断标准表格 + 关键数值表格 + 易错点列表）
- **第4章**：实战训练（3道真题，来源规则见"第三节"）
- **第5章**：考频分析 + 跨学科关联 + 审核清单

---

### Step 6: 汇总检查【关键步骤】

**6a. 来源验证汇总**：

Step 3-5 中已逐条验证，此步骤做汇总统计：
1. 扫描文档中所有 `verified:` 标记，统计 true/false/no_source 数量
2. 对仍为 `verified: false` 的条目，尝试二次检索（换关键词/换章节）
3. 最终仍无法验证的，保持 `verified: false` 并附注 `⚠️ 待人工核实`

**验证状态含义**：
- `verified: true` — 已通过文件验证，内容与教材一致
- `verified: false` — 未找到原文或内容不匹配，需人工核实
- `verified: no_source` — 无电子版教材，需人工补充页码

**严禁行为**：
- 禁止凭记忆编造教材页码
- 禁止伪造教材原文
- 如果无法验证，必须标注 `⚠️ 待验证` 而非写一个看似合理的页码

**6b. 完整性检查**：

自动生成检查报告：
```
完整性检查报告：
✅/❌ 第1章.1 题干完整性：与原文对比结果
✅/❌ 第1章.2 题目数量：X/X题全部提取
✅/❌ 第1章.2 答案对应：X/X题正确匹配
✅/❌ 第1章.2 六要素齐全：X/X题完整
✅/❌ 第1章.3 关联分析：已完成/缺失
✅/❌ 第2章 案例引用：X/X节点有对应
✅/❌ 来源验证：X条已验证 / X条待验证 / X条无来源
```

如有未达标项，提示补充。

---

### Step 7: 更新错误模式库（自增长）

处理新疾病时，自动执行：
1. 基于真题解析，识别 2-3 个该疾病的常见错误模式
2. 按 `mistakes_database.yaml` 的格式追加新条目
3. 在生成的工作流中引用新增的错误模式 ID

**错误模式 ID 命名规则**：
- 格式：`{疾病英文缩写}_{三位序号}`
- 缩写取自疾病英文名的常用缩写（2-4个大写字母）
- 已有缩写参考：MI（心肌梗死）、TB（结核）、HF（心衰）
- 新增示例：PE（肺栓塞）、DM（糖尿病）、SLE（系统性红斑狼疮）、CRF（慢性肾衰）、LC（肝硬化）、PU（消化性溃疡）、AP（急性胰腺炎）
- 序号从 001 开始递增，同一疾病内连续编号

## 三、实战训练题来源规则

**优先级**（从高到低）：

1. **历年真题文件**：从项目中已有的历年真题文件中提取同疾病/同系统的题目
2. **用户手动提供**：用户粘贴或指定题目来源
3. **标注"待补充"**：如果以上都没有，写 `⚠️ 训练题待补充（暂无历年真题数据）`

**严禁**：AI 自行编造模拟题。所有训练题必须有明确来源标注（年份+题号）。

## 四、.progress.yaml Schema

**存放路径**：项目根目录（与 `project.yaml` 同级），即 `D:\27临床医学考研 考纲+真题+教材流程版\.progress.yaml`

```yaml
# .progress.yaml — 工作流进度追踪
workflows:
  - id: "CARD-001"                    # 工作流ID
    disease: "急性心肌梗死"             # 疾病名称
    system: "心血管"                   # 系统分类
    source_questions: "2025年第84-86题" # 来源题号
    status: "waiting"                  # 状态（见下方流转规则）
    created_at: "2026-03-31"
    updated_at: "2026-03-31"
    verified_sources: 0                # 已验证引用数
    unverified_sources: 0              # 待验证引用数
    notes: ""                          # 备注

# 状态流转规则：
# waiting     → 已创建条目，尚未开始生成
# in_progress → 正在生成工作流文档
# generated   → 文档已生成，等待审核
# reviewed    → 已通过审核清单
# done        → 审核通过 + 来源全部验证
```

## 五、质量检查清单

审核清单的具体条目定义在 `template_v2.1.md` 的"5.4 审核清单"中（四层：完整性/准确性/深度/专家级）。

**执行规则**：
- Step 6 完成后，按 template 中的审核清单逐项检查
- 第一层（完整性）必须全部通过，否则不得标记为 `generated`
- 第二层中的 `verified: true` 检查项，必须基于实际文件验证结果
- 所有审核结果记录在生成文档的第5.4节中
