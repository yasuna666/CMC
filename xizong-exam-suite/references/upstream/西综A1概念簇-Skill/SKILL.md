# 西综A1概念簇-Skill

> **用途**：基于西医综合A型最佳选择题生成概念簇记忆卡片
> **核心创新**："合理扩展"概念簇 + 活文档逐年累加 + 弹性科目映射
> **适用题型**：A型最佳选择题（单句型A1 + 病例摘要型A2，题号不限）

---

## 零、核心设计变更（v1.0 → v1.1）

| 问题                       | v1.0设计                 | v1.1修正                                          |
| -------------------------- | ------------------------ | ------------------------------------------------- |
| **题号范围写死**     | 限定1-40题（基础三科）   | **全范围A型题**（题号不限，科目不限）       |
| **科目映射刚性**     | 附录写死"题1=绪论"       | **动态识别**（通过内容判断所属科目/章节）   |
| **数量假设不合理**   | "40题产出40个簇"         | **N个簇**（N由聚类结果决定，30-50均属正常） |
| **检索脚本过度设计** | Python+JSON索引          | **简化方案**（Obsidian标签/文件名/Grep）    |
| **示例错误**         | 钠钾泵"无特异性调节蛋白" | **修正为**"无钙调蛋白调节"                  |

## 一、核心设计哲学

### 1.1 从"孤立知识点"到"概念簇网络"

```
传统卡片：钙泵 → 孤立记忆
概念簇卡片：钙泵 + 钠钾泵 + NKCC2 → 对比网络
```

**合理扩展的"3同原则"**：

| 扩展条件         | 说明              | 示例                       |
| ---------------- | ----------------- | -------------------------- |
| **同章节** | 教材同一章节      | 钙泵与钠钾泵同在"物质转运" |
| **同机制** | 同类生理/生化机制 | 都是离子主动转运           |
| **同混淆** | 真题中出现过混淆  | 历年常对比考查             |

### 1.2 活文档（Living Document）

```
钙泵概念簇.md（逐年累加）
├── 初始（2025年录入）：基础内容 + 2025-第2题
├── 追加（2024年录入）：扩展内容 + 2024-第3题
└── 最终：完整概念簇 + 考频统计 + 多角度陷阱汇总
```

### 1.3 动态科目识别

不预设"题1-16=生理学"，而是通过**内容分析**动态识别：

```
题干关键词 → 科目判断
├── "钙泵""心动周期""动作电位" → 生理学
├── "糖酵解""DNA复制""蛋白质结构" → 生物化学
├── "坏死类型""肿瘤病理""炎症" → 病理学
├── "心音""杂音""心电图" → 诊断学
└── "COPD""心衰""肝硬化" → 内科学/外科学
```

生成动态的**题号-章节映射表**（每份真题独立生成）。

## 二、六要素卡片结构（v1.2更新）

每个概念簇文件必须包含以下六个要素，按顺序组织：

```
概念簇文件结构
├── 【真题呈现】（最前置）⭐ 新增 v1.2
│   ├── 完整题目（ABCD选项）
│   ├── 正确答案
│   ├── 详细解析
│   ├── 考查角度
│   └── 陷阱分析
├── 【核心概念】
├── 【教材原文】
├── 【概念簇对比】
├── 【干扰预警】
├── 【真题档案】（考频统计+关联簇）
└── 【速记卡片】
```

### 2.1 【真题呈现】（最前置）⭐ v1.2 新增

**位置**：概念簇最开始，Frontmatter之后
**目的**：让用户首先看到真题场景，理解考查方式，再学习概念
**来源**：100%复制真题原文，一字不减

**格式**：

```markdown
## 【真题呈现】（2025年第2题）

### 完整题目
> **关于钙泵的叙述，正确的是**
> 
> A. 细胞膜与内质网膜上的钙泵相同  
> B. 不具有特异性的Ca²⁺结合位点  
> C. 细胞内Ca²⁺通过与钙调蛋白结合可刺激其活动  
> D. 维持细胞内游离Ca²⁺浓度在一个较高的水平

### 正确答案
**C**

### 详细解析
①钙泵也称Ca²⁺-ATP酶...（保持真题解析原文）

### 考查角度
钙泵的分布（PMCA vs SERCA）、结构（特异性结合位点）、激活机制（钙调蛋白）、功能（维持低Ca²⁺）

### 陷阱分析
| 选项 | 陷阱类型 | 分析 |
|------|----------|------|
| A | 张冠李戴 | PMCA和SERCA是两种不同的钙泵 |
| B | 绝对化陷阱 | 两种钙泵都具有特异性Ca²⁺结合位点 |
| D | 功能混淆 | 钙泵维持的是低浓度，不是高浓度 |
```

---

### 2.2 【核心概念】

**要求**：一句话精准定义 + 一句话核心功能

```markdown
## 【核心概念】

**钙泵（Ca²⁺-ATP酶）**：一种利用ATP水解供能，主动将Ca²⁺从胞质转运至胞外或内质网的P型ATP酶。

**核心功能**：维持胞质游离Ca²⁺浓度处于极低水平（约为细胞外液的万分之一），是细胞钙信号调控的基础。
```

### 2.4 【概念簇对比】（核心创新）

**要求**：表格对比 + 关键差异标注

```markdown
## 【概念簇对比】离子泵家族对比

### 钙泵 vs 钠钾泵（核心对比）

| 特征 | 钙泵（PMCA/SERCA） | 钠钾泵 |
|------|-------------------|--------|
| **分布** | 细胞膜（PMCA）/内质网（SERCA） | 细胞膜 |
| **转运方向** | 胞质→胞外（PMCA）/胞质→内质网（SERCA） | 胞内Na⁺→胞外，胞外K⁺→胞内 |
| **化学计量** | 1ATP:1Ca²⁺（PMCA）/ 1ATP:2Ca²⁺（SERCA） | 1ATP:3Na⁺:2K⁺ |
| **调节机制** | 钙调蛋白激活 | 无钙调蛋白调节（受磷酸化、FXYD蛋白等调节） |
| **主要功能** | 维持胞质低Ca²⁺ | 维持膜电位和细胞体积 |

**【差异警示】**
- ⚠️ PMCA与SERCA是两种不同蛋白，不可混淆
- ⚠️ 钠钾泵不受钙调蛋白调节，这是与钙泵的关键区别
```

### 2.5 【干扰预警】（第五要素）

**要求**：基于真题总结常见陷阱

```markdown
## 【干扰预警】

### 模式1：张冠李戴（最高频）
- **陷阱表述**："细胞膜与内质网膜上的钙泵相同"
- **错误分析**：PMCA和SERCA是两种不同的钙泵
- **正确表述**：两种钙泵具有不同分布和化学计量

### 模式2：绝对化陷阱
- **陷阱表述**："不具有特异性的Ca²⁺结合位点"
- **错误分析**：两种钙泵均有特异性Ca²⁺结合位点
- **正确表述**：钙泵具有高度特异性的Ca²⁺结合位点

### 模式3：调节机制混淆
- **陷阱表述**："钠钾泵受钙调蛋白调节"
- **错误分析**：钠钾泵**不受**钙调蛋白调节（钙泵才受）
- **正确表述**：钠钾泵受磷酸化、FXYD蛋白家族等调节
```

## 三、文件组织规范

### 3.1 命名规则

```
{科目}_{章}_{全局编号}_{核心概念}概念簇.md

示例：
生理学_细胞的基本功能_001_钙泵概念簇.md
生理学_细胞的基本功能_002_纤溶系统概念簇.md
生物化学_蛋白质的结构与功能_003_蛋白质结构层次概念簇.md
诊断学_胸部检查_004_心音概念簇.md  ← 临床科目也适用
```

### 3.2 目录结构

```
output/概念库/A1概念簇/              ← 活文档，同一概念只有一个文件
├── by_subject/                      # 平铺存放，文件名编码科目和章节
│   ├── 生理学_绪论_001_内环境概念簇.md
│   ├── 生理学_细胞的基本功能_002_钙泵概念簇.md  ← 跨年累加
│   ├── 生物化学_蛋白质的结构与功能_003_蛋白质结构层次概念簇.md
│   └── ...
│
└── 全局索引.md
```

**文件名规则**：`{科目}_{章}_{全局编号}_{核心概念}概念簇.md`（科目和章节编码在文件名中，目录平铺不嵌套）

**活文档规则**：文件名不含年份。处理新年份时，先搜索是否已有同概念文件：有则追加（更新考频），无则新建。

### 3.3 检索方案（简化，三选一）

**方案A：Obsidian标签系统（推荐）**

在概念簇文件frontmatter中添加标签：

```yaml
---
tags:
  - 生理学
  - 细胞的基本功能
  - 钙泵
  - 离子泵
  - 张冠李戴
  - 2025
  - 第2题
---
```

在Obsidian中直接点击标签筛选。

**方案B：文件名Glob检索**

```bash
# 按科目
ls 生理学_*.md

# 按全局编号
ls *_001_*.md

# 按章节
ls */细胞的基本功能/*.md
```

**方案C：Grep内容检索**

```bash
# 查找包含特定陷阱模式的文件
grep -r "张冠李戴" --include="*.md" -l

# 查找特定年份的真题
grep -r "2025年（第2题）" --include="*.md" -l

# 查找特定概念
grep -r "【核心概念】.*钙泵" --include="*.md" -l
```

**不推荐**：复杂的Python脚本+JSON索引（维护成本高，收益低）。

### Step 1: 真题解析与科目识别

**输入**：选定年份的真题（A型题部分）

**处理**：

1. 逐题提取核心概念
2. **动态识别所属科目**（通过题干关键词）
3. **动态识别所属章节**
4. 标注陷阱模式
5. 生成**题号-章节映射表**（输出到日志）

**输出示例**：

```
2025年题号-章节映射：
├── 生理学（16题）
│   ├── 绪论：题1
│   ├── 细胞的基本功能：题2,3,4,12
│   ├── 血液循环：题5,6,7
│   └── ...
├── 生物化学（12题）
│   └── ...
└── 病理学（12题）
    └── ...
```

### Step 2: 概念聚类

**处理**：

1. 按"3同原则"识别可合并概念
2. 生成概念簇清单（N个簇，N根据实际聚类结果确定）
3. 分配全局编号（001-N）

**聚类示例**：

```
聚类前（40题）：
- 题2：钙泵
- 题12：NKCC2转运体
- 题15：钠钾泵（假设某年考到）
- （扩展）钙调蛋白（虽可能未考，但同机制）

聚类后（概念簇001）：
- 文件名：生理学_细胞的基本功能_001_离子泵家族概念簇.md
- 核心概念：钙泵（主）+ 钠钾泵 + NKCC2（扩展）
- 来源真题：2025-2, 2025-12, 假设2025-15
- 聚类理由：同章节 + 同机制（离子转运）+ 同混淆（历年对比考查）
```

### Step 3: 教材原文检索【带验证】

**模式A（用户提供教材）**：

1. 根据概念簇关键词检索教材文件
2. 提取相关段落
3. 标注精确位置（书名+章节+页码）
4. 标记 `verified: true`

**模式B（解析提取）**：

1. 从真题解析中提取关键信息
2. 整理为教材原文格式
3. 标注[待补充]和预计教材位置
4. 标记 `verified: no_source`

### Step 4: 概念簇生成

**批量生成**所有概念簇Markdown文件，按以下顺序组织：

**文件结构**：

1. **【真题呈现】**（最前置）：完整题目+答案+解析+角度+陷阱分析
2. **【核心概念】**：一句话定义+核心功能
3. **【教材原文】**：verified标记的教材引用
4. **【概念簇对比】**：表格对比+差异警示
5. **【干扰预警】**：陷阱模式详细分析
6. **【真题档案】**：考频统计+关联簇链接
7. **【速记卡片】**：可视化记忆工具
8. **【更新日志】**：版本追踪

**技术细节**：

- Frontmatter标签（供Obsidian使用）
- 内部交叉链接（同一簇内概念互链）
- 文件名符合规范：科目_章节_编号_概念.md

### Step 6: 质量检查【关键】


**严禁**：

- 禁止凭记忆编造教材页码
- 禁止伪造教材原文
- 无法验证必须标注 `⚠️ 待验证`

**6b. 六要素完整性检查**：

```
概念簇完整性检查：
✅/❌ [001] 离子泵家族 — 六要素齐全
✅/❌ [002] 内环境 — 六要素齐全
...
```

**6c. 交叉链接检查**：

```
交叉链接检查：
✅ [001] 中提到的"钠钾泵"有对应概念簇
✅ [001] 中提到的"NKCC2"有对应概念簇
⚠️ [003] 中提到的"糖酵解"暂无概念簇（可后续补充）
```

**注意**：不检查"概念簇数量是否合理"，只检查"每个簇是否完整"。

### Step 7: 陷阱模式库更新【自增长】

处理新真题后，自动执行：

1. 基于真题解析，识别该科目的常见错误模式
2. 按 `Skills/mistakes_database.yaml`（共享错误模式库）的格式追加新条目
3. 在生成的概念簇中引用新增的错误模式

### 6.3 状态流转规则

```
waiting ────────→ in_progress ────────→ generated ────────→ reviewed ────────→ done
   │                    │                    │                   │              │
   │ 创建条目           │ 开始生成           │ 文档已生成        │ 审核通过     │ 来源全部验证
   │ 尚未开始           │ 正在处理           │ 等待审核          │              │
   │                    │                    │                   │              │
   └────────────────────┴────────────────────┴───────────────────┴──────────────┘
                        ↑
                        │
                   可回退到任意状态
```

| 状态                  | 含义                     | 准入条件                 | 准出条件              |
| --------------------- | ------------------------ | ------------------------ | --------------------- |
| **waiting**     | 已创建条目，尚未开始生成 | Step 2完成               | Step 3开始            |
| **in_progress** | 正在生成概念簇文档       | Step 3开始               | Step 4完成            |
| **generated**   | 文档已生成，等待审核     | Step 4完成               | 第一层+第二层审核通过 |
| **reviewed**    | 已通过四层审核           | 四层审核全部通过         | 来源验证完成          |
| **done**        | 审核通过 + 来源全部验证  | verified_sources全部通过 | —                    |

### 6.4 更新时机

**Step 2（概念聚类）后**：

- 创建新条目，状态设为 `waiting`
- 填写 `id`, `concept`, `subject`, `chapter`, `source_questions`

**Step 3（教材检索）后**：

- 更新状态为 `in_progress`
- 更新 `verified_sources` 和 `unverified_sources` 计数

**Step 4（概念簇生成）后**：

- 更新状态为 `generated`
- 更新 `updated_at`
- 填写 `trap_patterns`, `related_clusters`

**Step 6（质量检查）后**：

- 第一层+第二层审核通过 → 更新为 `reviewed`
- 全部四层审核通过 + 来源验证 → 更新为 `done`

**追加新年度数据时**（如2024年）：

- 读取已有 `.progress.yaml`
- 更新 `current_batch.year` 和 `current_batch.status`
- 追加/更新概念簇条目（考频统计变化）
- 更新 `statistics` 统计信息
