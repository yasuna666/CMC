# 原六个西综模块兼容规则

上游完整副本在 references/upstream/，原 SKILL.md 作为按需读取的流程文档，统一入口不依赖嵌套 Skill 自动发现。

## 路径

原文 Skills/ 指向本包 references/upstream/（只读）。Windows 路径只视为作者示例，实际数据以用户配置为准，不探测或创建作者路径。真题流程可用原病例模块的 project.yaml.template；新命题采用独立 project.json，不混写。

所有输入输出和进度放用户工作目录，安装目录只读。运行上游辅助脚本前读参数，传入实际路径，不默认批量运行。上游未公开的示例、讲义和真题不可伪造。

## 路由与来源

分析整份真题先走原总调度，再把路由记录写入 `upstream-bridge.json`；讲义命题通过同一桥接清单读取题型模块的设计输入。模拟题即使借用原模块解析，也不得混入年度真题档案/考频。

桥接清单固定登记六个模块：总调度 `dispatcher`、A1 概念簇 `a1_concept`、A2 病例摘要 `a2_case_summary`、病例工作流 `case_workflow`、B 型配伍 `b_matching`、X 型多选 `x_multi`。题库顶层 `integration` 保存桥接清单路径和总调度引用，每道题的 `upstream_refs` 保存题型模块及设计转化目标。这样可追踪“哪个上游模块影响了题目设计”，又不会把上游文本冒充医学证据。

原文中的 165 题、固定年份、示例题号、已完成状态均为历史/示例，实际从用户材料识别。缺少官方依据不当成本次固定规则。

## 本套件覆盖规则

复用题型区别、概念对比、病例链和错误模式；所有分支采用下列来源规范：

- 不把解析改写后称教材原文，不用“预计页码”。
- verified 标记只能说明实际完成的文件核对，不能当权威医学认证。
- 原示例中的历史或简化表述不能充当新题医学依据。
- mistakes_database 是通用错误模式，不是用户真实错题记录；只有真实作答才能更新个人错误统计。
- 已生成不等于已复核，审核必须实际执行。
- 上游桥接引用是设计溯源；答案、选项判定和高风险结论仍须通过讲义/教材来源块和独立复核。

全部原文件字节不变，改进在外层入口及本兼容规则中完成。assets/upstream-manifest.json 只记录来源仓库、提交和文件路径。

## v2 适配优先级

出题与再练分支优先执行 module-adapters.md、upstream-bridge.md 和 learning-loop.md；原模块只按需提供设计方法，不执行真题档案及考频写入。原 Skill 的示例概率、未核验医学断言及固定路径不作为本次规则。使用实际条目时记录知识 ID、原始来源和定位；对历史概念卡必须重新核对本轮讲义证据。
